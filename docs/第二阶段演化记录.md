## 需求带来的问题与增量选择

1. 原题目只有问卷内身份，无法表达可复用资源历史。因此增加独立题目ID和不可变版本ID，原实例ID及嵌入内容继续保留。
2. 原ownerId权限只支持个人问卷，不能直接拿题目来源代替问卷归属。因此增加可选communityId并集中管理／统计权限，旧缺省仍为个人。
3. 单纯先查成员后写题目有退出竞态。因此加入事务内社区栅栏，成员退出、移除与依赖成员的写触碰同一文档。
4. 自动同步最新版会改写历史答卷解释。因此共享与快照固定versionId，升级必须显式，并保留旧规则做完整校验。
5. 直接用source标签而不比对内容会使跨卷统计失真。因此禁止普通保存换引用、修改引用内容或静默脱离，提供专用选题／升级／脱离接口。
6. 复用原问卷统计的查询方式可能混合用户、版本与重复实例。因此新增MongoDB聚合管道，按授权scope和固定resource/version汇总，明确单位为实例回答次数。
