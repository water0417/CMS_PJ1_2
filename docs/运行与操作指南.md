# 运行与操作指南

## 入口与首次安装

仓库根目录即项目目录，包含 package.json；请在该目录打开 PowerShell。安装 Node.js 22 LTS（包含 npm）、Git、Docker Desktop，启用 Linux containers 并启动 Docker Desktop。

```powershell
git clone https://github.com/water0417/CMS_PJ1_2.git
cd CMS_PJ1_2
npm.cmd ci
docker compose up -d --wait
npm.cmd run db:init
npm.cmd run build
npm.cmd run seed
npm.cmd start
```

seed 默认准备人工演示账号user、aaa～eee及《今天是什么颜色呢》9题定义；已有同名问卷不覆盖，不生成答卷。原系统样例用seed:system单独初始化。seed不是启动依赖；密码及保护策略见README和《人工测试数据与记录》。也可在项目目录执行 `./启动项目.ps1 -Install -Demo`。PowerShell 若阻止本地脚本，可逐条执行上述命令，无需修改系统执行策略。

| 入口         | 地址或命令                  | 用途                   |
| ------------ | --------------------------- | ---------------------- |
| 正式构建网页 | http://127.0.0.1:3000       | 前后端单端口访问       |
| 登录／注册   | http://127.0.0.1:3000/login | 注册后登录             |
| 工作台       | http://127.0.0.1:3000/      | 管理自己的问卷         |
| 编辑         | /editor/:id                 | id 为问卷数据库 ID     |
| 填写         | /survey/:publicId           | 使用发布后的分享链接   |
| 统计         | /statistics/:id             | 仅创建者可访问         |
| API          | http://127.0.0.1:3000/api   | 契约见 API说明.md      |
| 开发模式     | npm.cmd run dev             | 网页5173，代理后端3000 |
| 数据库       | 127.0.0.1:27018             | MongoDB 7 副本集 rs0   |

不要同时运行 start 与 dev 的两份后端。Ctrl+C 停止当前应用；`docker compose stop` 停止数据库且保留命名卷。重新启动数据库无需再次 seed。不要删除命名卷来解决普通启动问题。

## 完整使用流程

1. 注册账号或用演示账号登录，进入工作台。不同账号只能管理自己的问卷。
2. 创建问卷，在编辑器设置标题、说明、匿名和重复提交选项，添加题目、选项、必答及校验限制。先保存，再发布。
3. 新草稿采用专属分支模式。规则中非 END 目标自动标为分支，未命中时仅顺序进入后面的通用题；页面显示实际入口。没有通用题不能发布。分支之间需要显式跳转，不自动成组。
4. 当前系统统一采用专属分支机制，不提供逐份升级按钮。历史数据维护见《系统统一分支机制迁移》，正常新建问卷无需迁移操作。
5. 发布时配置截止时间（可不设），从工作台复制分享链接。已关闭或已截止问卷不能继续收集。发布快照不随草稿编辑变化。
6. 填写者先登录；允许匿名时可选择匿名。匿名不代表免登录，也不绕过每账号次数限制。
7. 每道题确认答案后继续；可选题可以明确留空确认。返回只能查看当前有效路径中访问过的题，查看不清空。确认改答后由后端保留有效答案、清理失效分支；新分支需补答。真正循环要求重新确认目标，180次提醒、最多200次确认。
8. 到达提交确认后提交。系统使用后端保存答案并验证路径；网络异常或版本冲突时读取最新状态，不要自行改写答案状态。返回查看后仍可能允许提交，是否可提交由后端决定。
9. 创建者从工作台打开统计，查看整卷、逐题选项计数、文本内容和数字平均值。只有正式提交且属于有效路径的答案参与统计；未提交过程不计入。

## 配置、验证和排错

默认配置可直接本机运行。API 的 dotenv 从运行目录 apps/api 读取 `.env`，seed 从项目根读取 `.env`；统一配置可在当前 PowerShell 设置环境变量 MONGODB_URI、PORT。模板见根目录 .env.example。不要上传真实凭据。

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run test:integration
```

集成测试需先构建，使用3101和独立 survey_studio_test_* 数据库，不启动正式3000服务。可通过 TEST_MONGODB_URI 指定测试副本集；脚本替换数据库名，不使用正式数据。结果保存在 test-results/integration.json，测试数据库保留供检查。

| 问题                   | 处理                                                       |
| ---------------------- | ---------------------------------------------------------- |
| Docker 无法连接        | 启动 Docker Desktop，确认 Linux containers，再执行 compose |
| MongoDB 提示不支持事务 | 使用项目副本集27018，执行 db:init；独立27017不能代替       |
| 副本集刚初始化尚未就绪 | 等待几秒后重新启动应用                                     |
| 3000或3101被占用       | 停止对应旧实例；不要随意终止其他服务                       |
| 页面内容仍旧           | 重建后重启 start，再刷新；dev 使用源码监听                 |
| NO_ENTRY               | 至少保留一道没有被任何规则指向的通用题                     |
| CONFLICT               | 读取最新草稿或填写状态后重试；升级须重新审阅               |
| 普通题被跳过           | 检查它是否被任意规则指向，新模式下此时必为分支题           |

服务仅绑定本机。跨机器分享需要另行部署 HTTPS、认证数据库及反向代理；本机链接不能直接给远端用户使用。

### 广场筛选与邀请故障恢复（2026-10-29）
广场输入标题后点击搜索；题型与“我公开的”可组合，条件变更回第一页。重置清空全部条件；翻页保留条件。邀请信封显示“暂不可用”时并非没有邀请，自动刷新已暂停；打开面板手动刷新。社区概览失败仅影响该卡，点击“重试概览”；确认权限失效后不提供资源入口。最新实际结果见《第二阶段前端接入与验收》末节及 `design-preview/square-followup/`。

社区详情直接展示左侧问卷、右侧题库，无需先进入其他列表。窄屏上下排列；社区内新建/编辑题目完成后返回当前社区。空白题目切换题型不弹确认，已有输入时继续确认并保护输入。

选题弹窗按每次保存的内容逐条展示，直接点击“选用此题”；“预览”可查看该次内容。列表按题目分页，每页展开这些题目的全部保存记录。

草稿归属：问卷设置→问卷归属，创建者选择个人空间或已加入社区，点击“修改归属”并确认。先处理未保存修改。社区成员访问范围随迁移改变；已发布问卷不可修改归属。升级本次后端代码后须重启API服务。
公开选题：从题库选题→题库空间→公开题库，预览后点击“保存并选用”；会先保存为个人副本，再加入当前问卷，不改变问卷归属。选入失败时个人副本可能已保存，可重试。

### 题目历史与独立副本
“保存修改”为原题新增历史；“另存为新题目”为独立题目，原题不变。更多→历史记录可查看修改依据与恢复来源，最新和正在查看内容有文字标记；恢复生成新记录。副本来源只展示当前有权限的标题和保存次数，无权访问时显示来源不可查看。选题弹窗区分同题最新与历史内容，选旧内容不会恢复题库或修改其他问卷。
