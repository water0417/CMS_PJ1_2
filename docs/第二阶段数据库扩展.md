# 第二阶段数据库扩展设计

在原MongoDB问卷结构上增加题库、共享与社区，不采用关系数据库，不推倒第一阶段。既有8个集合保留，survey/definition/response读取兼容无新增字段的数据。

## 身份、嵌入与引用

题目资源library_questions._id、内容版本question_versions._id、问卷实例questions[].id是三个独立身份。资源维护最新指针；版本不可变；实例保存完整嵌入内容和固定source引用。问卷跳转只引用本问卷实例ID，题库content不带跨题跳转。

嵌入用于问卷整体校验、原子草稿保存及不可变发布；引用用于复用身份、历史、共享和跨卷统计。填写不依赖题库联网读取，也不追随最新指针。副本生成独立资源和v1，provenance仅记录来源，不建立自动同步或跨用户答卷权限。

## 新增集合与索引

| 集合                  | 主要字段                                                                                                   | 访问模式／索引                                                                                                      |
| --------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| library_questions     | scopeKey、ownerId或communityId、createdBy、title、type、latestVersionId、revision、provenance、dataVersion | scopeKey+updatedAt；scopeKey+title；communityId                                                                     |
| question_versions     | questionId、number、content、parentVersionId、restoredFromVersionId、authorId、contentSchemaVersion        | questionId+number唯一；authorId+createdAt                                                                           |
| question_shares       | kind、questionId、versionId、senderId、recipientId或token、status、writeSerial                             | token稀疏唯一；recipientId+status+createdAt；kind+status+createdAt；senderId+kind+createdAt；senderId+createdAt+_id |
| question_share_copies | shareId、userId、questionId、versionId、initialQuestion                                                    | shareId+userId唯一，保证接收幂等                                                                                    |
| communities           | name、adminId、revision、writeSerial                                                                       | adminId+createdAt                                                                                                   |
| community_memberships | communityId、userId、role、active                                                                          | communityId+userId唯一；userId+active+communityId                                                                   |
| community_invitations | communityId、senderId、recipientId、status、revision                                                       | communityId+recipientId唯一；recipientId+status+createdAt                                                           |

所有集合带createdAt/updatedAt。个人题归属scopeKey=personal:userId；社区题为community:communityId；个人题有ownerId且无communityId，社区题相反，MongoDB oneOf约束防止混用。版本content仅保存题型、标题、说明、必答、选项、矩阵行、校验，MongoDB禁止夹带额外顶层实例／跳转字段。

Mongoose字段约束与MongoDB $jsonSchema双层验证；复合唯一索引防并发重复。内容合法性、父版本所属、引用内容一致、来源权限等跨文档规则在服务层事务验证。版本不可变指应用接口只insert不update历史；数据库账号仍应限制在受控后端使用，MongoDB管理员直接写库不属于API权限模型。

## 既有集合增量

- surveys增加可选communityId（无字段视为个人），保留ownerId用于创建者身份；新增communityId+deletedAt+createdAt索引。
- draft.questions增加可选source={questionId,versionId}，仍嵌入原题目全部内容；无source保持本地题。
- survey_versions.definition固定嵌入source及内容，不改历史快照；增加来源组合索引。
- drafts来源组合索引用于使用查询；responses答案键仍为实例ID，schemaVersion和答案结构不改变。
- users._id继续作为用户ID，没有新增重复内部用户ID。

## 并发一致性

### 不可变版本与恢复

题目修改需revision。事务读取归属权限、匹配当前revision，更新最新指针并revision+1，insert新版本，parentVersionId为提交时最新版本。两人提交同revision只能一人成功，后者409；失败事务不残留版本。恢复也是新版本，额外记录restoredFromVersionId，不删除v2/v3或改写v1。

### 成员权限栅栏

所有依赖社区身份的写操作在事务内：读取active成员→写communities.writeSerial→执行业务写。退出、移除和邀请接受也写同一社区文档。并发事务发生写冲突后由MongoDB驱动重试，重试重新验证成员。若移除已经提交，写不能继续沿用旧成员快照。跨社区资源选用会依序触碰涉及社区的栅栏，事务重试处理竞争。

退出设置active=false，不删除审计关系；不自动转存社区题。旧已接受邀请的幂等响应不重新激活成员，管理员重新邀请会提升邀请revision，避免旧客户端接收新邀请。管理员不能退出或自我移除，当前不提供转让。

### 投递与链接

共享固定versionId。接收在事务中写共享writeSerial，查询share_copies唯一键，复制个人题及v1，写接收结果；并发接受复用同一题。接收记录保存初始版本ID和小型题目元数据快照，重复接收回放首次结果，不被接收者后续编辑改变；版本内容仍从不可变v1读取，不重复存储content。撤回也写同一共享记录；撤回先提交则接收重试后404，接收先提交则副本已经独立，不受撤回影响。拒绝是独立终态；已接受投递不能再拒绝。

链接读取与转存都校验随机token。撤回项从收件箱与广场移除，不因列表接口绕过撤回。社区题对外分享先显式转存个人副本，避免外部能力链接绕过成员退出约束。

### 问卷修改

所有管理写操作在同一事务中进行当前权限检查，社区管理也触碰栅栏。source只能通过后端选题／升级接口建立，普通保存不能换source。内容与固定版本深度比较，不一致拒绝；脱离必须显式操作。发布再次校验source与完整定义，按固定版本冻结。

升级保留实例ID和全部原跳转，先生成完整候选定义并用原引擎校验。删选项导致条件引用无效时拒绝，不能偷偷删规则或指向其他选项；矩阵行和选项差异在预览列出。

## 权限与统计

个人问卷仅创建者管理和统计。社区问卷只有当前成员中的创建者或管理员可管理，任何当前成员可统计。个人问卷用社区题仍归个人，社区其他人看不到其标题和答卷。

使用查询在MongoDB内联接有权限的surveys，输出实例级引用，并过滤软删除；不返回隐蔽引用数量。跨卷统计在MongoDB中联接responses→surveys权限范围→survey_versions→固定source实例，核对activePath且答案实际存在。没有把所有答卷find到内存再循环。文本和值分布分页20，矩阵及排序按题目定义上限返回分组；排序不push全部位置数组。

统计单位instance-answer，同卷重复实例各算一次；不同版本和转存副本完全分开。来源作者不获得其他人的统计权。已离开社区的人不能请求社区scope，仍可看本人个人问卷固定实例的个人scope数据，这不开放社区题库或其他版本。

## 版本号分工

| 字段                          | 含义                | 本次处理                                 |
| ----------------------------- | ------------------- | ---------------------------------------- |
| dataVersion                   | 新题目资源结构版本  | 初始1，非内容修改次数                    |
| contentSchemaVersion          | 题库content结构     | 1，九题型原结构                          |
| question_versions.number      | 单题内容历史v1、v2… | 每次修改／恢复增一                       |

| Definition.routingMode        | 跳转语义            | 保留legacy-v1与exclusive-branches-v1解释 |

## 初始化与历史兼容

启动connectDatabase自动幂等创建新增集合、索引和验证器。也可先执行npm.cmd run db:phase2，仅初始化结构，必须连接副本集。没有逐题回填、按标题去重、重写答卷或快照的迁移。旧本地题需要用户按需保存题库，然后显式选用才有来源。回滚应用前保留数据库备份；不要删除新增集合来恢复第一阶段，已有第一阶段文档和提交历史仍可追溯。

发送者分页列表通过会话senderId匹配后，在同一MongoDB聚合facet中计算total和分页rows；仅分页后联接固定版本和最小接收者信息。新增senderId+createdAt+_id索引支持跨类型的创建时间稳定排序，已有共享无需迁移或重写。

## 2026-10-29 补充接口的数据与索引复用

用户名精确查找直接读取users.usernameNormalized既有唯一索引，响应仅id/username。邀请列表名称来自当前页communityId/senderId的批量最小投影，不冗余存储；待处理总数按recipientId+status查询，复用community_invitations既有复合索引，不按当前页计算。没有新增“已读”字段。

编辑另存使用library_questions及question_versions现有事务创建资源与v1，在既有provenance中记录已验证的questionId、versionId及channel=library-save-as。不会修改来源内容和旧快照，不需要提升dataVersion、contentSchemaVersion、问卷schemaVersion、发布版本或跳转语义版本。

社区概览实时统计active成员、社区独立题资源以及deletedAt为空/缺失的社区问卷。不会将题目版本数当题目数，也不会因个人问卷引用社区题就计入社区问卷。复用现有社区成员和题目索引；问卷计数沿用现有模型，未为本次小规模概览增加强制迁移。前后验证当前成员，非成员无概览权限。

## 2026-10-29 广场搜索访问模式

公开分享仍引用不可变question_versions，筛选读取该固定content.title/type；不为搜索冗余复制原题最新标题。先按kind/status/mine过滤共享，再关联匹配questionId/versionId及内容条件，统一facet分页计数；现有共享与固定版本索引继续使用。包含搜索转义用户正则并限制120字符，不承诺任意包含搜索能用标题前缀索引；本阶段未引入全文引擎或改写历史版本。未新增集合或schema版本。
