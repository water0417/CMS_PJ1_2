## 路由与操作

| 路由                                               | 用途                                                 |
| -------------------------------------------------- | ---------------------------------------------------- |
| `/library`                                         | 个人题库；服务端标题搜索、题型筛选、分页             |
| `/library?communityId=…`                           | 当前成员社区题库                                     |
| `/questions/new`                                   | 创建九种题型，首次保存 v1；可携带 communityId        |
| `/questions/:id`                                   | 新版本编辑、只读历史、恢复、来源、转存与指定版本共享 |
| `/question-insights/:id?versionId=…&communityId=…` | 固定版本、指定空间的统计与授权使用情况               |
| `/square`                                          | 公开固定版本、预览、转存、我公开的及撤回             |
| `/shares`                                          | 收件箱、我发出的；类型/状态筛选与服务端分页          |
| `/question-links/:token`                           | 登录返回原链接、专用分享读取、携带 token 接受        |
| `/communities`、`/communities/:id`                 | 社区、邀请、成员、退出、社区题库与问卷               |

顶部用户名可展开用户 ID 并复制。新建问卷可选个人或当前社区。普通成员进入社区问卷只获得统计入口，管理员及仍为成员的创建者才有管理操作。

编辑器的“从题库选题”可指定版本；每题“存入题库”创建独立题库内容；“检查题库更新”展示差异与规则失效原因，明确确认后升级；“脱离后本地编辑”经确认解除引用。引用内容只读，跳转规则仍独立可配。专用接口操作前，如有本地输入，必须选择保存、取消或明确放弃；保存失败不继续。每次成功同步服务端 revision。

题库只发送内容字段，不包含实例 id、source 或 jumpRules。修改选项/矩阵文字保留 ID。历史恢复生成新版本，不改变历史和问卷。409 不覆盖本地输入，提供服务器内容比较后再决策。题库内容、问卷、邀请的 revision 分开维护。

## 运行和复验

正常运行继续使用已有 `.env` 和 `npm run dev`，生产式运行 `npm run build` 后 `npm start`。第二阶段数据库初始化遵循现有后端指南 `npm run db:phase2`，不要对正式数据运行测试种子。

本轮独立预览：`http://127.0.0.1:3104`，测试账号 `ui_admin`、`ui_member`、`ui_outside`，测试口令仅保存在本地种子脚本；均为独立测试库中的虚构账号。成员在验收结束时已退出/被移除，复验社区需重新邀请接受。测试 API 服务环境的 `MONGODB_URI` 必须使用独立数据库名（例如 `mongodb://127.0.0.1:27018/survey_studio_phase2_ui_1793175000000?replicaSet=rs0&directConnection=true`），`PORT=3104`。先构建前端，再以独立环境启动 API，最后运行 `npx tsx scripts/seed-phase2-ui.ts`；该脚本会创建测试业务记录，不得指向正式环境。补充分页数据可运行 `node scripts/phase2-ui-additional.cjs`。

常见操作顺序：创建题库 v1 → 修改新版 → 选择历史预览/恢复 → 指定固定版本共享或入卷 → 主动检查更新并处理规则差异。统计先选固定版本，再选个人/当前社区，副本与原题分开统计。
